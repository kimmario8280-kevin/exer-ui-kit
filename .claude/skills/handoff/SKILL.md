# handoff — 세션 인계

세션에서 진행한 작업을 다음 사람(또는 다음 세션의 나 자신)이 처음부터 다시 파악하지 않아도 되도록, 저장소 루트의 `.handoff.md` 파일에 상태를 기록한다.

## 언제 쓰는가

- 사용자가 명시적으로 "/handoff", "handoff 해줘", "인계 문서 만들어줘"라고 요청할 때
- 긴 작업 세션을 마무리하며 다음 세션으로 넘길 때
- 작업이 중간에 막혀서 다른 사람에게 넘겨야 할 때

## 절차

1. **`.handoff.md`가 이미 있으면 먼저 읽는다.** 이전 인계 내용과 지금 세션에서 바뀐 부분을 구분해야 덮어쓰기로 정보가 유실되지 않는다.
2. 이번 대화에서 실제로 한 일을 근거(파일 경로, 커밋, 실행한 명령과 그 결과)와 함께 정리한다. **추측하지 말고 실제로 확인된 것만 ✅에 넣는다** — 예: "테스트 통과"라고 쓰려면 실제로 테스트를 돌려서 통과한 결과를 봤어야 한다.
3. 시도했지만 실패했거나 포기한 접근은 ❌에 적는다. 왜 안 됐는지 한 줄로 남겨서 다음 세션이 같은 시도를 반복하지 않게 한다.
4. 아직 안 한 일, 다음에 이어서 할 일을 ⏳에 체크리스트로 적는다. 모호한 "계속 작업" 대신 구체적인 다음 액션으로 쓴다.
5. 아래 템플릿 형식으로 `.handoff.md`에 쓴다(Write 도구 사용, 기존 파일 있으면 Read 먼저).
6. 사용자에게 `.handoff.md`에 인계 내용을 저장했다고 짧게 알린다.

## 템플릿

```markdown
# Handoff — {{YYYY-MM-DD}}

## ✅ 완료 (검증됨)
- [x] {{한 일}} — {{근거: 파일/커밋/실행 결과}}
- [x] {{한 일}} — {{근거}}

## ❌ 시도했으나 실패 (반복 금지)
- [ ] ~~{{시도한 것}}~~ — {{실패 이유}}

## ⏳ 다음 할 일
- [ ] {{다음 액션 1}}
- [ ] {{다음 액션 2}}

## 참고
- {{현재 브랜치, 관련 이슈/PR, 참고 파일 경로 등 알아야 할 맥락}}
```

## 주의사항

- ✅ 항목은 반드시 "검증된 증거"와 함께 적는다. 코드를 작성했다는 것과 그게 동작한다는 것은 다르다 — 테스트를 돌렸다면 그 결과를, UI 변경이면 브라우저로 확인한 사실을 근거로 남긴다.
- ❌ 항목은 비난이 아니라 정보다. "왜 실패했는지"가 핵심이므로 원인을 한 줄로 명확히 쓴다.
- ⏳ 항목은 다음 사람이 바로 실행할 수 있을 만큼 구체적으로 쓴다 ("버그 수정" 대신 "index.html의 select() 함수에서 탭 전환 시 iframe이 재생성되지 않는 문제 수정").
- 이 파일은 저장소에 커밋할지 여부를 사용자에게 확인한다(민감한 내부 상태가 아니라면 커밋해도 무방하지만, 커밋은 사용자가 명시적으로 요청했을 때만 한다).
